# Guardrails: Localization

SOP: `sop/localization.md`. Applies once `docs/project/flutter/project-rules.md` PR-F2 records the string source. Single-language L1/L2 apps using a constants class still follow I18N-1, I18N-4 and I18N-5.

**I18N-1** — User-facing text MUST come from the string source recorded in PR-F2 (`AppLocalizations` from `.arb`, or the constants class). Literals in widgets, dialogs, snackbars, validators and `Failure` messages MUST NOT be added.
Check: `rg -n "Text\(\s*'[A-Za-z]|(title|label|hint|message|content):\s*'[A-Za-z]" $PRES $STATE` → new hits are violations.

**I18N-2** — With l10n: every key MUST exist in the template ARB (`app_en.arb` or the project's template locale) with an `@key` description; translations MUST NOT be generated by concatenating strings at runtime.
Check: `flutter gen-l10n` succeeds; untranslated-messages file is reviewed.

**I18N-3** — Counts and gender MUST use ICU `plural`/`select`; `count == 1 ? 'item' : 'items'` MUST NOT be added.
Check: `rg -n "== 1 \? '" $PRES` → must be empty.

**I18N-4** — Dates, times, numbers and currency MUST be formatted with locale-aware formatters (`intl` `DateFormat`/`NumberFormat` with the current locale). Manual string assembly (`'$day/$month'`, `'\$' + price`) MUST NOT be used for display.
Check: `rg -n "'\$' *\+|\$\{\w+\.(day|month)\}/" $PRES` → review.

**I18N-5** — Layout MUST be direction-aware when any supported locale is RTL: use `EdgeInsetsDirectional`, `AlignmentDirectional`, `start/end`; directional icons MUST mirror.
Check (RTL projects): `rg -n "EdgeInsets\.only\((left|right)|Alignment\.(centerLeft|centerRight)" $PRES` → review.

**I18N-6** — Strings MUST NOT be embedded in images or hardcoded in backend-independent enums shown to users; server-provided display text MUST arrive already localized or be mapped through the string source.
